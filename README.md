# Limit Order Book Matching Engine

A C++-based Limit Order Book Matching Engine that processes limit and market orders using price-time priority. The project integrates with Worklet 1's order book implementation to execute matching, manage order quantities, and record trades.

## Overview

The project implements the matching component of an electronic trading system. It accepts buy and sell orders, matches compatible orders according to price-time priority, updates the order book, and records executed trades.

The project is organized into worklets, with Worklet 1 providing the order book and Worklet 2 implementing the matching engine.

## Features

- **Limit Orders:** Match orders when their prices are compatible; retain unfilled quantities in the order book.
- **Market Orders:** Execute against available opposite-side orders without applying a limit-price restriction; discard any unfilled quantity.
- **Price-Time Priority:** Prioritize better prices and process orders at the same price in FIFO order.
- **Partial Execution:** Support orders being filled across one or more matching orders.
- **Trade Recording:** Record individual executions with trade IDs, buy and sell order IDs, execution prices, and quantities.
- **Order Book Management:** Update remaining quantities, remove fully executed orders, and maintain the order book through Worklet 1.
- **Modular Design:** Separate order validation, matching logic, trade recording, and matching-engine coordination.

## Architecture

The matching engine uses the existing Worklet 1 `Book` directly.

1. **Order Validation:** Checks common order fields and applies order-type-specific validation.
2. **Matching Engine:** Coordinates order submission and routes orders to the appropriate matcher.
3. **Limit Order Matcher:** Matches limit orders against compatible orders on the opposite side of the book.
4. **Market Order Matcher:** Matches market orders against available orders on the opposite side, starting from the best available price.
5. **Trade Recorder:** Stores the trade records generated by successful executions.
6. **Worklet 1 Order Book:** Maintains orders and price levels and provides operations for accessing, updating, and removing orders.

## Matching Rules

### Limit Buy

- Matches against the lowest available sell price while that price is less than or equal to the buy limit.
- Executes at the resting sell order's price.
- Places any remaining quantity in the buy side of the book.

### Limit Sell

- Matches against the highest available buy price while that price is greater than or equal to the sell limit.
- Executes at the resting buy order's price.
- Places any remaining quantity in the sell side of the book.

### Market Buy

- Consumes available sell orders, starting with the lowest ask.
- Executes at each resting sell order's price.
- Discards any unfilled quantity after available matching opportunities are exhausted.

### Market Sell

- Consumes available buy orders, starting with the highest bid.
- Executes at each resting buy order's price.
- Discards any unfilled quantity after available matching opportunities are exhausted.

### Price-Time Priority

Price priority determines which price level is matched first. Within a price level, older orders receive priority over newer orders. Partial execution preserves the resting order's position in the FIFO queue.

## Trade Records

Each successful execution produces a separate trade record containing:

| Field | Description |
|---|---|
| `tradeID` | Unique identifier assigned to the execution |
| `buyOrderID` | ID of the participating buy order |
| `sellOrderID` | ID of the participating sell order |
| `price` | Execution price of the resting order |
| `quantity` | Number of units executed |

A single incoming order may generate multiple trade records when it matches multiple resting orders.

## Build Instructions

### Prerequisites

- GCC/G++ with C++14 support
- Git
- A terminal such as PowerShell on Windows or Bash on Linux

### Compile

Run the following command from the repository root:

```bash
g++ -std=c++14 -Wall -Wextra \
-Iinclude -Iworklet2/include \
src/*.cpp worklet2/src/*.cpp worklet2/test_main.cpp \
-o orderbook
```

On Windows, the executable will typically be named `orderbook.exe`.

### Run

**Windows PowerShell:**

```powershell
.\orderbook.exe
```

**Linux:**

```bash
./orderbook
```

## Testing

The test driver in `worklet2/test_main.cpp` is used to test matching-engine behavior.

The initial tests cover:

1. Limit buy matching a resting limit sell, including partial execution.
2. Limit sell matching a resting limit buy, including partial execution.
3. Market buy execution across multiple sell price levels.
4. Market sell execution across multiple buy price levels.

Further testing should cover FIFO ordering at the same price, non-crossing limit orders, complete fills, unfilled orders, invalid inputs, and boundary cases.

## Scope

The current Worklet 2 scope includes:

- Limit and market buy/sell matching
- Price-time priority
- Partial and complete execution
- Trade generation and recording
- Order book updates and Worklet 1 integration

Time-in-force policies such as DAY, GTC, IOC, and FOK are outside the current scope.
